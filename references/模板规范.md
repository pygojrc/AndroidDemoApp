# 模板规范

## 技术基线

- `minSdk = 33`
- `compileSdk = 37`
- `targetSdk = 37`
- Java toolchain 17
- Kotlin DSL 与 Version Catalog
- AGP 内置 Kotlin，不应用旧的 `org.jetbrains.kotlin.android` 插件
- Jetpack Compose、Material 3、稳定版 Navigation 3
- `versionCode = 2`、`versionName = "0.1.1"`

Gradle、AGP、Kotlin、Compose 和 AndroidX 版本必须固定。更新依赖后重新执行完整构建与 lint，不把仅能同步依赖视为模板可用。

## Demo 与项目生成

`assets/demo/` 使用真实包名 `io.github.pygojrc.androidmoderndemo`，自身始终可独立编译。不要将不可构建的模板占位符写入 Demo。

使用 `scripts/创建项目.py` 完成：

- 复制 Demo；
- 修改应用名称、根项目名称、namespace 和 applicationId；
- 修改 Kotlin 包声明和源码目录；
- 可选处理定制图标；
- 拒绝覆盖非空目标目录。

## UI 边界

- 页面使用 Compose，不创建传统 XML layout。
- `ModalNavigationDrawer` 包裹根 `Scaffold`；Scaffold 统一管理 Top App Bar、底部导航、Snackbar、FAB 和页面内容。
- 页面内容应用并消费 `Scaffold` 的 `innerPadding`。
- Top App Bar 负责顶部安全区域，底部 Navigation Bar 负责系统导航栏区域。
- Scaffold 只额外处理横向 safe drawing Insets，避免顶部和底部重复留白。
- 输入页面在需要响应键盘的滚动容器上应用 IME Insets。
- 应用内悬浮框限制在已扣除 Scaffold Insets 的页面内容区域内。
- 页面不得无条件叠加 `systemBarsPadding()`、`safeDrawingPadding()` 或 `navigationBarsPadding()`。

## 导航

- Demo 包含“首页”“组件”“设置”三个一级页面。
- 底部导航和左侧侧边菜单共享一级页面及返回栈。
- 首页是退出应用前的根页面。
- 从其它一级页面按返回键先回首页。
- 再次点击当前导航项不重复加入返回栈。
- 业务页面只接收导航回调，不直接持有导航实现对象。

## Demo 组件

- 组件页集中提供 Snackbar、AlertDialog、ModalBottomSheet、DropdownMenu、Checkbox、Switch、Slider 和 TextField。
- 根 Scaffold 提供只在组件页显示的可展开 FAB。
- 可拖动悬浮框属于应用内 Compose 组件，不申请悬浮窗权限、不启动 Service。
- 跨应用悬浮窗不进入默认模板；明确需要时再加入 `SYSTEM_ALERT_WINDOW`、`WindowManager` 和 Service 生命周期处理。

## 主题

- 默认跟随系统浅色或深色模式。
- 默认启用 Android 动态配色，同时保留浅色和深色回退色板。
- 页面颜色和文字样式来自 `MaterialTheme`，避免散落硬编码。
- 系统栏图标明暗跟随主题。

## 图标

- 每个新应用默认生成与主题匹配的国漫风美少女头像。
- 头像原图至少为 1024×1024，人物关键特征位于 adaptive icon 中央安全区域。
- 不包含文字、水印、品牌 Logo 或复杂边框。
- 同时提供普通、圆形和 Android 13 themed icon 声明。
- 无法生成图片时保留模板图标，并明确标注为占位图标。

## 默认不加入

- Hilt 或其它依赖注入框架
- Room、Retrofit、Ktor
- 多模块和 Clean Architecture
- 登录、网络权限、存储权限和后台服务
- 跨应用系统悬浮窗
- Analytics、广告 SDK、自动更新
- 发布签名和 CI/CD

只有实际业务需要时才以最小范围增加这些能力。
